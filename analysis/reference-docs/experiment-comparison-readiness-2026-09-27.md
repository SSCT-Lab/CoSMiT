# 实验比较分析就绪度审查（2026-09-27）

## 结论

现有数据足够开展**结果分布、组件输出差异、请求完成率和受控机制演示**；尚不足以支持“CoSMiT 在真实迁移测试上更准确地验证测试意图保持”这一主要实验结论。主要问题是样本与研究问题的对应关系、独立标签和基线有效性，不只是数据量。

本次检查读取了 benchmark 实现、research-data 的逐项结果及压缩执行记录，并补充检查其附近的迁移验证开发集。做了离线计数与文件哈希核对；未重新执行框架实验或调用模型。按照作者组会反馈，D0028 不作为有效反例、真实错误或论文动机证据；历史原始数据保持不变，也不擅自将它标成正确样本。

## 1. 已有数据规模与可用范围

| 数据 | 候选 / 家族 | 执行记录 | 当前用途 |
|---|---:|---:|---|
| research-data/2026-09-17/controls | 10 / 1 | 60 对 | 受控检查、实现健全性 |
| discovery | 69 / 24 | 13,248 对 | 固定输入上的方法输出分布 |
| unseen | 12 / 6 | 2,304 对 | 预留家族上的程序比较；不是外部迁移测试留出集 |
| migration_verification_v1 开发集 | 12 / 4 | 261 对，含透明性检查 | 源测试—候选—断言—见证机制演示 |

前三部分共 91 个候选、15,612 对执行记录。公开程序部分为 81 个候选、30 个家族，每个候选 64 个输入、每个输入 3 次重复，共 15,552 对。重复次数、输入数、API 别名和迁移方向不能当成相互独立的样本量。

公开部分适配了 1,401 个 counterpart 库存中的 81 个（约 5.78%）。适配和准入选择需要公开，不能从当前子集外推整个库存。

### 公开程序数据与当前研究目标之间的距离

这些候选主要来自 DLLens 公开函数配对，源性质由实验另行构造。数据条目记录 API、来源与哈希、输入和注册条款，但不提供原始迁移测试断言的完整评估链。因此，它主要检验程序在注册条款上的一致性，不能直接等同于原有测试意图是否保留。

尤其需要修正 `self-test` 的表述：`benchmark/baselines/run_experiment.py` 的 summarize 在所有行均为 executed 时就置为 passed。该字段不能据此解释为“原候选测试的全部原始断言通过”。

公开轨迹中的数值违反仅出现于 D0028；排除其作为有效发现后，当前公开包没有可据此主张的有效正例。这不意味着其余候选已被独立证明正确，也不能计算错误检出召回率或宣称 100% 准确率。

## 2. 当前基线结果可以比较到什么程度

### 公开 81 个候选的主要输出

| 方法 / 组件 | 原始输出分布 | 可解释范围 |
|---|---|---|
| DLLens comparator port | 80 无差异、1 有差异 | 后者是 D0028，不能计作有效发现 |
| CoSMiT 注册条款检查 | 80 测试输入上支持、1 反驳 | 同上；支持不等于普遍正确 |
| Direct LLM | 12 完成、69 失败 | 完成率约 14.8%，先分析运行可靠性 |
| Trace LLM | 0 完成、81 失败 | 当前没有可比较的有效语义判定 |
| IntentTester verifier port | 67 accepted、7 rejected、7 undetermined | 组件输出；无独立 gold，不能当准确率 |
| 自定义 target-TDL extension | 66 accepted、8 rejected、7 undetermined | 必须与官方组件区分 |
| DocTer port | 37 satisfied、43 undetermined、1 violated | 局部约束检查，不能当意图保持标签 |

主模型记录共 455 次请求，278 次完成、177 次失败。另有 33 次重试（17 次完成）以及主记录离线解析恢复 7 次的补充口径。主结果、重试结果和解析恢复应分别报告，不能混合挑选最有利结果。completed 仅代表产生可解析的输出，不代表语义正确。

Trace LLM 的公开失败中有 76 个 RuntimeError、5 个 URLError；现有错误分类不足以认定其全部因上下文过长。Direct LLM 也有响应拒绝/格式问题和网络、超时问题。应先修复少量预检查样本的调用链，再冻结设置做正式运行；失败不得视为正确或意图违反。

### 公平比较的限制

- DLLens 与 CoSMiT 复用相同执行观察，当前公开实验使用固定输入，没有自适应搜索。因此不能据此得出反例搜索效率优势。
- DLLens comparator 使用 squeeze/flatten 和较宽的数值容差（atol=0.1）；CoSMiT 同时检查值、形状、类型并使用不同容差。差异可能来自检查规则本身。需要同输入、同数值容差的对照，再分别消融形状、类型、绑定和断言敏感性。
- IntentTester 和 DocTer 是适配后的局部验证组件。source TDL 的输入是注册 contract，并非真实源测试自动抽取的原始意图。不能把这些结果写成完整官方系统之间的优劣比较。
- 当前 CoSMiT 行内检查计时使用缓存 Observation，排除了实际框架执行；LLM 请求耗时又受暂停、并发等影响。二者不能直接组成端到端效率排名。费用记录还存在缺失 usage，不宜给出完整成本结论。

## 3. 更贴合论文目标的开发集

`datasets/migration_verification_v1` 与 `artifacts/migration-verification-pilot-v1-final` 保存了更直接的测试级验证记录：4 个本地生成原候选、8 个人工变体，覆盖 abs/square/subtract/add。

- 4 个原候选得到 tested-inputs 上支持，8 个受控变体得到反驳。
- 10 个候选自身测试通过；其中 **5 个同时通过自身测试、观察到目标调用，仍被验证器反驳**。
- 12 个见证分属 8 个候选：5 个行为输入见证、4 个断言敏感性见证、3 个绑定见证。不能写成发现 12 个独立错误。
- 12 个候选的接口透明性检查均通过。删除断言、放宽容差、恒真断言等案例已经有有限的断言敏感性验证记录。

这批记录能支撑“仅通过执行与调用检查仍可能遗漏意图问题”的受控演示，尤其值得在论文中利用。但源测试是带上游依据的开发重建，并非上游测试原样切片；4 个原候选经过有目的选择，8 个错误由人工构造，没有独立标注和未曝光留出集。不能作为真实错误率、通用准确率或外部系统比较结果。

还需明确：abs 的一般数值义务属于重建时增加的范围，MV002 不能描述为原上游 signed-zero 测试自身的迁移错误。所有探针都是预先注册的固定探针，不能用于自动搜索优势结论。

**复现缺口：**README 指定的 `benchmark/migration_verification/` 在当前 checkout 不存在，而历史 run-manifest 记录了 build/run/verify/worker 脚本哈希。需要恢复对应版本的脚本，再复核重放；现有结果文件本身不能替代可执行实验流程。

## 4. 环境和档案一致性

公开包的实际执行记录为 TensorFlow 2.20.0、PyTorch 2.9.1、NumPy 2.1.3；部分基线说明及规格依据仍涉及 TensorFlow 2.16.2、PyTorch 2.1.0 等版本。迁移验证开发集另用 NumPy 2.4.6。应分别记录每批环境，并核对规格依据是否适用于实际运行版本。

公开数据包自带的 `--verify` 在 README 哈希处失败。逐文件复核发现 32 个文本文件的字节哈希不匹配，但将 CRLF 规范成 LF 后均与清单一致；压缩日志字节哈希匹配。这符合 checkout 换行转换，未由此发现文本内容差异，但不能称原始字节校验通过。建议通过换行保留规则或规范发布归档恢复校验，不要直接重写历史哈希掩盖问题。

`benchmark/rqs` 另有 24 个参考/人工错误程序、4 策略、10 seeds 的历史设计（960 campaigns），它们不是 960 个真实迁移样本；original 策略采用预选见证。当前检查未发现该 README 所指历史运行目录可供完整复核，不应与上述公开包混合做主结果。

## 5. 建议补实验顺序

1. **先补真实候选和独立判定依据。**保存完整源测试、已有迁移测试、来源版本、原始断言、适用输入域和规格证据。纳入真实有效、真实违反、无法判定三类情况；给出准入排除账本。正例应经独立复核，特别排除规格不一致、超出源意图和数值容差误报。D0028 不用于补正例。
2. **把开发集与正式评估分开。**现有 12 个案例用于机制开发；正式样本按源测试/家族分组留出，避免同一测试衍生变体泄漏。先获得可靠标签，不必先追求某个任意样本数。
3. **冻结同候选上的基线与消融。**明确是否比较全系统或组件，统一输入预算、重复次数、数值规则和环境；单列执行、绑定、行为条款、断言敏感性的增量效果。当前 DLLens 函数包不能替代测试级候选集。
4. **修复模型基线并单列无法判定。**用开发样本确认请求和解析链路；固定重试策略。正式报告覆盖率/完成率、已判定部分的质量和整体未决比例，避免只统计成功请求。
5. **最后评估效率与搜索。**若论文声称自动寻找反例，应增加预算一致的实际搜索、独立随机种子和端到端成本记录；固定探针试验单独报告。正式统计以候选或独立来源为单位，重复运行用来检查稳定性。

现在即可制作输出分布表、模型失败类型表、受控机制案例表；正式的准确率、真实缺陷数量、显著优于基线和搜索效率结论应保留为空，等待上述证据。
