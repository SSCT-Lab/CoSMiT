## 一个统一单元包含什么

每项在`units/<ID>/unit.json`登记：

1. 原始来源、家族、批次和两侧counterpart代码。
2. 行为实验输入与原契约（原始批次）或冻结输入及参考（扩充批次）。
3. 如有测试对：源/目标测试正文、上游方法位置、源码快照、操作替换路径。
4. 具体检查义务、输入生成方式、执行环境、适配限制。
5. 已有测试运行记录及基线/透明性/扰动资格。
6. 缺失材料、评价用途与独立标签空值。

`units.json`是全量机器索引；`cohorts.json`分别给出行为清单、27个构造测试单元清单和空的正式完整意图清单。9个人工变换只关联已有基础对象，不加入110个主候选。

这是**统一证据与方法输入包**，不是已经接入所有基线的独立一键运行发行包。重放仍依赖原项目运行环境、expecttest和runner路径配置；本次没有声称27个样本已在所有方法上完成重跑。

## 原始80个：补证可行性检查

检索的是本地PyTorch/TensorFlow稀疏checkout的Python文件，保存HEAD提交、实际文件哈希和源码快照。两套checkout提交分别为：

- PyTorch：d38164a545b4a4e4e0cf73ce67173f70574890b6。
- TensorFlow：72fbba3d20f4616d7312b5e2b7f79daf6e82f2fa。

这两个本地快照尚未与实验运行版本建立对齐；不能凭HEAD名称声称文件就是实验对应版本。实际消费字节由input-hashes和包内SHA256固定。

检索按源框架与精确API属性引用匹配；通用`_test_reference_numerics`或`_compareCpu`另列为helper线索，不据此推断该API已经完成注册。

详见[原始80个补证表](initial-80-gap-table.md)，逐项方法名、行号、断言位置和helper依赖保存在各unit.json的source_test_leads中。

### 为什么53个引用线索不能直接变成53个测试对

- D0001的torch.abs出现在归一化或pad等测试里，可能只是辅助计算，并不代表该方法的主要意图就是abs性质。
- D0011有专门的exp测试，也有其他功能测试中的exp调用，必须筛选匹配当前有限实数域的场景。
- D0030在TensorFlow一元测试中有acos引用，但依赖_compareBoth/_compareCpu等helper；这些helper还包含梯度检查。只保留前向结果而删梯度会改变原义务，必须明确限定构造范围，不能冒充完整迁移。
- D0012与H003/H008/H010/H011/H012在当前本地文件中未建立直接源测试线索。可以继续补取对应版本测试和OpInfo登记，但本次未把通用helper当作已匹配测试。
- 即使找到合适上游测试，把DLLens counterpart放进去仍是本次构造的操作替换测试，不会自动成为DLLens历史输出的完整迁移单测。

## 两条实验清单现在如何使用

### 行为实验

继续使用110个候选，维持原分批输入域和环境解释。已有106个有限范围支持、3个行为违反、1个绑定未决的统计不变。

### 测试意图实验

以27个构造测试单元作为候选基础；尚不直接计算正式准确率。先固定要评价的义务，排除或明确记录桥接不能保留的类型、别名、布局、梯度等性质，再建立有依据的保持/违反参照。保留基线失败与适配失败，不能只挑通过样本计算总体表现。

原始80个暂时不自动加入此清单。后续若构造新测试，应在其unit下增添新test版本及来源，保留原counterpart身份，避免改变历史数据含义。

## 下一步具体入口

建议先扩展已有27对中基线与声明范围可用的对象，构造“仍有非恒真断言，但检查错误对象/遗漏必要性质”的对照，并按原义务逐项验证。此前9个简单开发样本中静态规则与CoSMiT打平，这一步才能检查动态验证是否有额外收益。

与此同时，原始80个的补证从少量有明确专用方法的候选开始，例如D0011；先解决上游版本、helper闭合和输入域，再扩大。不要一次将53个语法命中全转成实验样本。

已有基线的缺失依赖仍按`controlled-baselines-corrected-2026-10-10/baseline-status.json`处理；本次统一数据结构不等于那些方法已经可运行。

## 校验与复现

```powershell
python benchmark/baselines/build_unified_evaluation_units.py artifacts/analysis/unified-evaluation-units-rerun
```

输出目录必须尚不存在，需要NumPy和已存在的本地框架checkout。程序核对注册上游快照、执行AST核验，确认110个单元与27对/1,290条测试记录的计数。`SHA256.json`固定生成数据与快照，README为另行整理的解释文档。

没有新增框架/模型调用、没有改写原数据，没有访问其他datasets目录。独立标签字段全部为空，不把方法输出或语法命中转成gold。
