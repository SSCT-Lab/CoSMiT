# 9个受控样本的方法评价

日期：2026-10-10。正类定义为“声明范围内的断言检查能力丢失”。数据含3个基础测试各3个版本：3个原样保持对照、3个删除断言、3个恒真断言，共9个开发样本。它们不是9个独立真实迁移，也不是盲测集。

五种已运行方法的判定覆盖率均为9/9，没有未决。精确率分母TP+FP为0时记为未定义，不填0或100%。Direct LLM的9项为not-run，没有加入其他方法的分母，也没有当成9个漏检。

准确率=(TP+TN)/9；精确率=TP/(TP+FP)；召回率=TP/(TP+FN)。丢失样本有6个，保持样本有3个。当前五种方法的误拒绝均为0/3，这个极小规模结果不支持普遍误拒绝率结论。

## 方法具体做了什么

### 正常运行检查

读取三次original模式下的源/目标测试结果，双方均通过则报告保持。9个样本都正常通过，所以6个丢失版本全部漏检。这是run-pass启发式基线，不是完整意图判断。

### 操作观察相等比较

在正常基线与透明性门槛通过后，比较双方未扰动的首次操作观察。counterpart未修改，删断言不改变操作结果，所以全部判断保持。本方法是此次实现的比较器，**不是完整DLLens复现**。

### 两个静态基线

- 断言存在检查：AST中存在assert或assert*方法调用即认为仍有检查。可以检出删除断言，无法检出恒真断言。
- 排除字面恒真断言的存在检查：进一步忽略`assert True`与`self.assertTrue(True)`。这不是一般的“有效断言判定器”，只是一条明确的简单规则。它恰好可以识别本包两种修改，所以取得满分。

这些基线扫描整个保留类正文，没有通用控制流、数据依赖或语义分析能力。它们在复杂真实代码中可能误判。本次特意保留第二个静态基线，防止将过于简单的构造错误当成CoSMiT独有优势。

### CoSMiT核心＋测试结果记录适配器

本次实际调用`src/cosmit/engine/certification.py::certify`及其evaluate路径，没有修改核心源码。新增适配器位于`benchmark/baselines/evaluate_controlled_assertions.py`。

输入不再是counterpart计算出的张量值，而是**在指定扰动下测试是否触发断言拒绝**：

1. 原样执行、observe和reinject均通过；observe/reinject观察一致。
2. 确认源断言拒绝相关扰动，且错误栈归属于保留测试正文。
3. 确认双方收到相同的扰动观察，并重新计算形状/数值扰动公式。
4. 目标运行异常、缺失观察或不等观察均不冒充意图违反。
5. 将源/目标的拒绝状态编码为布尔Observation，由`oracle='outcome'`比较。
6. 首次违反后读取另外两次已保存执行作稳定确认，每个sample最多6组成对记录读取。positive仅限声明的条款全部合格并通过。

E018仅登记shape条款，不把源方法本来就接受的数值扰动算成意图丢失。E022/E030登记值与形状条款。

这是**新的、显式登记的测试结果观察器接入**。输入义务和扰动已有登记，不代表CoSMiT自动从任意测试中推断完整意图，也不等于先前110个候选使用的操作行为比较流程。由于观察门槛和反例确认依赖同一开发批次记录，本结果是功能接入检查，不构成独立有效性证据。

本轮没有重跑TensorFlow/PyTorch，复用了此前270次单侧测试执行。新增模型调用为0。核心消耗的“executions”是读取已有成对记录的次数，不能当成新增框架执行数或公平的端到端成本；不报告速度优势。

## 如何理解这个结果

现在已经可以在这个**受控开发包**上计算准确率和召回率；标签含义是指定断言义务下的构造丢失。结果证明正常通过、操作输出相等都不足以代表检查能力保持。

**还没有证明CoSMiT优于简单静态检查。** 排除字面恒真断言的基线与CoSMiT同为6TP、3TN。若只列较弱基线，会夸大本批材料的说服力。

后续最有价值的扩展是保留看起来有效的断言、却检查错误对象/错误性质或只覆盖部分必要条件的变换。例如检查输入与自身、比较无关计算结果、只保留形状而失去数值检查。每个变换都必须依据原义务并通过独立的丢失见证确认；保留正常对照，不只挑CoSMiT成功的案例。应先冻结变换规则与范围，再跑各方法。

不将这9个构造版本加到原110个公开候选中，不把6个人工错误加到3个真实counterpart行为问题中，也不将本表作为整篇论文的最终效果结论。
