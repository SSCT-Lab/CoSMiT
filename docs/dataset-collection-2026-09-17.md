## 源性质如何取得

1. 从公开源 API/源模型提取操作、维度、返回值和可观察行为；原函数、原输入及出处原样保留。
2. 下载固定版本规格：PyTorch 2.1.0 的 `_torch_docs.py`，TensorFlow 2.16.2 的 23 份数学算子说明，共 24 个文件；登记文档 URL、哈希和 PyTorch 对应行号。
3. 建立 24 个数学家族的源性质注册表，每项覆盖元素值、形状、浮点 dtype。分别限制定义域，例如 log 输入严格为正、sqrt 非负、反三角函数限制于 [-1,1]、tan 避开极点。当前只检查声明的有限浮点范围，不推及整数、复数、稀疏、梯度或整个 API 语义。
4. 使用 Python 标量数学参照，从实际类型转换后的源输入计算预期值。预先固定 float32/float64 容差；先完成所有源程序核验，再执行目标程序。模型判断不充当数学真值。
5. 模型级性质从源末层及原形状断言取得，包括输出宽度、batch、dtype，以及适用时的概率范围和概率和。数值等价另行要求权重和输入布局对齐。

实现：`benchmark/baselines/collect_public_corpus.py`、`source_property_reference.py`、`run_source_evidence.py`、`probe_besser_sources.py`、`validate_public_pairs.py`。

## 本轮实际结果

- 69 份 API 候选均通过源性质核验。每份 64 个边界/随机输入，覆盖两种 dtype、四种形状，每输入真实执行 3 次；共 13,248 次源执行和 13,248 次目标执行。
- 68 份目标在已测输入上满足性质；1 份公开 `torch.trunc` 对应函数稳定违反值性质。例：源端 `trunc(-8)=-8`，目标函数输出 -7。原因是目标表达式对所有负数使用 `floor(x)+1`，包含了负整数。该对应函数不保持源性质，不归因为 TensorFlow 实现缺陷。
- 对 `trunc` 原公开 17 个输入，以固定种子生成并各执行 3 次，共 51 对，未出现输出不一致。新增边界输入发现的问题，在相同输入下也被 DLLens 原输出比较器检测到；不声称这是超越输出比较的收益。
- BESSER 的 10 份源模型中，7 份完成 42 次源执行并通过已登记性质。另 3 份保留未决：两个 TF 网络需要 `tensorflow_addons`，一个 PyTorch CNN-RNN 在所构造输入上出现通道维度冲突。后者仍需核实输入布局与程序适用条件，不能直接标为迁移缺陷。
- BESSER `tf_tutorial`、`lstm` 两组公开模型使用固定权重复制代码对齐后，分别完成 6 对执行，全部满足形状和值容差。
