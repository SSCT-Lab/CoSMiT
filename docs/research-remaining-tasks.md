# CoSMiT 论文剩余任务与验收标准

更新：2026-09-12。用于协作推进，不是实验完成报告。以当前研究计划中的三个问题为准：RQ1 错误迁移检测、RQ2 反例有效性、RQ3 诊断与条件精化。旧的表示／任意 adapter 合成路线不作为本清单的默认目标。

## 当前基础

- [x] 修复已知四类静态误接受，拒绝截断模型响应和空测试获得正向支持。
- [x] 实现条款观察、预算搜索、反例稳定复验、受限缩减和条件样本外重检。
- [x] 实现语法级 Mapping IR，未知调用与控制流保留为 residual，不当成语义证明。
- [x] 将 12 条既有性质接为 24 个参数化开发程序，保存 960 个开发 campaign。
- [x] 建立 IntentTester 公开候选索引与定向回放入口；完成 KATRER-inspired 三条生成／判断试跑。
- [x] 补齐 NumPy 2.3.0 下的 KATRER 三条源测试回放；目标 CuPy 仍未验证。

以上不等于完整研究计划完成。实验次数不是独立候选数，参考来源不是 gold 正确标签，静态 IR 不是运行时绑定证据。详细历史进展见 [开发进展](research-rq-progress-2026-09-09.md)。原始实验日志不随本次仓库同步发布。

## P0：先解决所有 RQ 共用的可信度问题

| ID | 待补内容 | 验收标准 |
| --- | --- | --- |
| P0-1 | 复核 cross-entropy 与 variance 的数值容差 | 固定原始输入、dtype、源／目标双轨迹及独立数值依据；区分映射错误、可解释浮点差异和不合理 oracle。不为改善结果直接放宽容差 |
| P0-2 | 实现真实候选的参数化执行接口 | 可注入新输入并执行原候选逻辑，保留 setup、调用与断言；记录变换位置和代码哈希；不能用重写的 kernel 冒充真实系统候选 |
| P0-3 | 完善运行时目标绑定与有效测试门槛 | 区分 import、实际调用、断言覆盖；未收集、全部 skip、环境错误和未知 residual 不能给正向结论；增加正负对照 |
| P0-4 | 冻结证据状态与预算协议 | 明确声明域和已测试集合、源／目标执行与复验成本；正向仅限有记录的实际输入；不足以复验的差异保持未决 |
| P0-5 | 完善可恢复、可核查的实验账本 | 保存配置、运行版本、源文件哈希、所有尝试及失败类别；恢复执行不覆盖已有产物，失败不从结果分母中消失 |

## RQ1：能否发现错误迁移，且不过度拒绝正确候选？

- [ ] 补齐尚未完成的 23 条开发性质主标注；按单一主 oracle 拆分，记录有效域、排除域与固定证据。
- [ ] 核对计划中的 20–30 个有依据 API 对及 40–60 条规则目标，逐项列出已实现／未实现覆盖；数量达标不能代替规则有效性。
- [ ] 为新输入域重新核验参考候选，加入正确、错误、设计差异、目标不支持和无法判定的案例，不能按 REF/MUT 文件名自动生成 gold。
- [ ] 完成独立复核：复核者不看系统 verdict、反例和答案映射；保存分歧与裁决。AI 复查不能代替第二位研究者。
- [ ] 使语法 Mapping IR 接入执行义务，记录显式转换、目标调用和未知残余；报告覆盖率而非假定全覆盖。
- [ ] 在共同候选集上跑 compile-only、self-test、target-binding、官方原输入回归、直接 LLM 判断和 CoSMiT。明确各 baseline 的适用性，不把“不适用”当失败。
- [ ] 补充可核验的官方有效映射／计划中的 ONNX 对照；说明其与被测任务是否同域。
- [ ] 分层报告受控 mutant、参考程序、真实系统输出和历史迁移；加入目标调用正确、自测通过但语义错误的真实案例，测量超过简单绑定检查的增量收益。

验收产物：候选级来源与独立标签表、共同样本 baseline 结果、precision/recall/F1、正确候选误拒绝、可执行但错误检出率、未决与覆盖统计。独立标签不足时只报告诊断计数，不发布 gold 性能。

## RQ2：条款驱动探针能否更有效地找到反例？

- [ ] 将历史手选 witness 与官方原始回归输入分开，补齐后者；不把已知反例当作公平的原输入 baseline。
- [ ] 补齐 LLM 输入探针对照。已有部分响应与失败记录，但尚非完整共同样本结果；新尝试应有独立记录，模型输出只能作为数据，不能执行生成代码。
- [ ] 在共同环境、候选和执行预算下比较官方原输入、随机、通用边界、LLM 与条款策略；分开报告模型成本和运行成本。
- [ ] 从当前条款模板推进到明确、可复用的选择规则；记录策略如何使用源条款，避免读到候选标签或预先知道的反例。
- [ ] 补入数值边界覆盖；当前模板漏掉参考程序上的浮点差异，是需要保留的负面证据。
- [ ] 对随机策略使用预先固定 seed 列表；增加消融，区分条款信息、选择顺序、稳定复验和缩减的作用。
- [ ] 冻结方法后评估未见 API 组，不能先看留出失败再更新规则并继续称原轮 held-out 结果。
- [ ] 预先确定统计单位、配对比较、置信区间与多重比较处理；按候选／API 组处理相关性，不能把 seeds 当独立候选。

验收产物：发现率、到首次稳定反驳的执行次数与耗时、预算耗尽／未决比例、受限缩减前后大小及消融结果。不能仅在成功样例上比较效率；没有发现反例的 campaign 也必须进入统计。

## RQ3：能否定位原因并恢复有用的成立条件？

- [ ] 从单条预登记 clause 扩展到多条款义务，检查同一失败是否存在多个可能原因。
- [ ] 为 invalid mapping、design divergence、target unsupported 和 suspected target violation 建立独立判据；只有排除映射与环境问题后才能提出目标缺陷怀疑。
- [ ] 增加源／目标规格证据和人工根因标注，与当前仅输出失败条款的实现区分。
- [ ] 定义条件语言与候选生成机制；当前 squeeze/clamp 两个手工模板的独立输入重检，不等于一般自动条件推导。
- [ ] 限制条件复杂度与最低保留域，拒绝空域、单个 witness 或任意排除困难样本的“修复”。
- [ ] 将 discovery 与 validation 分开，条件选择不能使用验证结果；补测边界附近及被排除区域。
- [ ] 获得独立条件参照或明确有限评估域后，再计算条件边界 precision/recall；记录错误精化与人工复核时间。

验收产物：逐条款／根因诊断表、独立复核结果、条件表达式与保留域、验证轨迹、错误精化率和人工成本。没有独立真值时不报告条件准确率。

## 外部验证与投稿材料

- [ ] 完成 IntentTester 真实候选的源测试对齐及独立复核；公开输出回放与完整生成流程复现分开归因。
- [ ] 获得 KATRER 缺失的图谱／Fingerprint／API 验证中间材料，或者明确只保留 inspired pilot，不冒充官方 baseline。
- [ ] 确认固定 CuPy 运行环境并实际执行目标候选；服务器连接状态需重新检查，历史网络失败不代表永久不可用。
- [ ] 接入尚未覆盖的随机状态性质；固定随机数／统计 oracle 与稳定性协议。
- [ ] 收集真实 issue/PR/历史迁移案例，固定修复前后 commit、源性质与可重复反例；区分已知缺陷回放与新发现。
- [ ] 完成相关工作中 CEGIS、差分测试、性质测试等引用核验；不提前声称方法优先性。
- [ ] 用正式结果替换论文占位符，补充失败案例、消融、限制、AI 使用说明及目标会场格式要求。
- [ ] 整理可公开的环境锁定文件、获取上游材料的步骤、脱敏结果与匿名 artifact；确认第三方再分发许可。

## 推进顺序与协作依赖

1. P0 数值证据审查、真实候选执行接口与记录完整性。
2. 小型独立复核集和完整共同样本 baseline。
3. RQ1/RQ2 开发验证与方法冻结，再开放留出评估。
4. RQ3 独立诊断／条件评估和真实 issue/PR 外部验证。
5. 正式结果统计、论文修订与公开 artifact。

代码实现、数据整理和开发运行可继续推进；独立人工复核需要另一位研究者，完整 KATRER 复现需要合法可用的上游材料及运行环境。二者不是增加本地运行次数能够替代的条件。

完成任务时必须附证据路径或 commit，再更新复选框。尚未执行的任务不填写预期数值，受阻项不直接勾选完成。
